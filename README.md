# 游戏连点器（GameClicker）
主要用途：二游自动过剧情，一键点击跳过加确定选项；
全屏游戏中可用的连点器：**按一下你自定义的按键，就在鼠标所在位置持续点击**，间隔可自定义；**可记录多个坐标，各配热键，按热键自动点过去；多个坐标共用一个热键时按顺序依次触发**。

- 免安装、免依赖：单个 `GameClicker.exe`，Windows 自带运行库即可运行（需 .NET Framework 4.x，Win7 SP1 及以上系统自带）
'- **主界面大小可拖拽调节**（右上角也可最大化），尺寸自动保存，下次启动原样恢复
- **多套游戏配置**：每个游戏一套序列，检测到游戏在前台时**自动切换**；Ctrl+点击多选序列可批量删除/启停'
- 支持全屏游戏：使用底层 `SendInput` 注入 + 低级键盘钩子，不依赖窗口焦点
- 体积约 76 KB，免安装免依赖（但**强烈建议以管理员身份运行**，原因见下文）

---

## 快速开始（3 步）

1. **运行 `GameClicker.exe`**（默认会请求管理员权限，点"是"。可在「程序行为」里取消勾选「默认以管理员身份运行」来跳过 UAC）
2. **设置触发键**：点「按下以设置按键」，然后按下你想用的键（默认 **F3**）
3. 点「保存设置」——完成。之后双击运行（或从托盘唤出），按触发键即可连点。

进游戏后，**按 F3 开始连点，再按 F3 停止**。

想固定点某个位置？把鼠标移过去，按 **F7** 记录（或点「+ 记录当前鼠标位置」），在列表里给它设个热键，之后按那个热键就会自动点过去。全屏游戏里可用「**批量录点…**」一次记多个坐标。

## 功能说明

### 触发键

| 项目 | 说明 |
|---|---|
| 键盘按键 | 点「按下以设置按键」后直接按任意键（Esc 取消）。支持 F1–F24、字母、数字、小键盘、方向键等 |
| 鼠标按键 | 可选左键 / 右键 / 中键 / 侧键 X1 / X2 |
| 触发方式 | **切换**：按一下开始，再按一下停止（默认）<br>**按住**：按住时连点，松手停止 |
| 紧急停止 | 独立于触发键的"刹车键"，默认 **F12**。任何时候按下都立即停止连点 |
| 吞掉触发键 | 默认开启。连点器会拦截该键，游戏不会同时收到，避免触发游戏自身功能（如 F3 常被用作游戏内功能键） |

> 在连点器窗口自身处于前台时，触发键不会生效，方便你正常操作界面。

### 点击设置

| 项目 | 说明 |
|---|---|
| 点击间隔 | 1 – 60000 毫秒。可用数字框精确输入，或拖动滑块，或点 `10ms / 20ms / 50ms / 100ms / 200ms` 快捷按钮 |
| 点击鼠标 | 左键 / 右键 / 中键 |
| 按下时长 | 每次按下保持多久（默认 15ms）。**太短游戏可能识别不到**，若游戏里点击无效可调大 |
| 跟随鼠标位置 | 默认。点击始终落在鼠标**当前**所在位置 |
| 锁定启动时的位置 | 锁定按下触发键那一刻的坐标，之后不管鼠标在哪都点那个点。可点「把锁定点设到鼠标处」重新指定；配合"自动拉回指针"可维持视角 |
| 自动拉回指针 | 仅锁定模式。若指针在两次点击间被移开，自动拉回锁定点 |

**间隔稳定性**：引擎用高精度计时器（`Stopwatch`）+ 混合睡眠/自旋，并调用 `timeBeginPeriod(1)` 提升系统计时精度。实测平均间隔与设定值误差 ≤ 0.25ms（见下方测试数据）。10ms 档可稳定跑满 100 次/秒。

### 多套游戏配置（自动切换）

在「坐标点」页顶部可以**新建多套配置**，每套有自己的序列，并绑定一个游戏进程名（如 `starrail.exe`）。

绑定的游戏**一到前台**（全屏、无边框都有效），连点器就自动切到那套配置；切到别的程序不主动换，避免来回跳。
绑定进程名不用手敲——点「**浏览…**」直接选游戏的 exe 即可。
新建的配置是**空白**的（不含任何序列），每个游戏从零录自己的操作；配置名随时可改（「改名」按钮，所有配置都能改）。程序没有「默认」配置——第一次启动会自动创建「配置1」。
检测每约 0.4 秒一次，但取进程名用的是轻量内核调用（实测 0.03ms/次），常驻运行的 CPU 占用可忽略。

- 配置按名字存在 `%APPDATA%\GameClicker\Profiles\<名称>\`，复制这个目录就能把整套设置（含绑定关系）带给别人
- 检测每约 0.4 秒一次（轻量内核调用，CPU 占用可忽略），切换后气泡提示
- 新建的配置会**复制当前配置作为起点**，不用从零重录

### 坐标点页（序列）

> 界面分三个标签页：**触发键**（怎么开始连点）/ **坐标点**（序列与批量录点）/ **程序行为**（托盘、自启、权限），点顶部标签切换。

批量录点产出的**一条采集 = 一条序列**：一串按录制顺序排列的坐标，**共用一个热键**，按一下就依次点完一轮。
单点的序列（只记了一个位置）也用同一套逻辑：仍可选「按一次点一次」或「按一下开始/再按停止」。

| 项目 | 说明 |
|---|---|
| 列表 | 一行一个坐标点，列出 **序号 / 备注名 / 坐标 / 热键 / 点击方式**。序号对应批量录点时屏幕上的圆圈标记 |
| 左侧方框 | 勾选 = 启用该点的热键；取消勾选 = 暂时停用（坐标仍保留） |
| **记录坐标…** | **窗口自动让开，你在屏幕上点哪儿就记哪儿，可一次记多个；录完按 Esc 回来确认** |
| 改键 | 给选中的坐标点设热键：点「改键」→ 按任意键 |
| 清除热键 | 只清掉热键、保留坐标（之后只能从界面点「点过去」） |
'| 上移 / 下移 | 调整顺序。多条序列共用同一热键时，这个顺序就是触发先后 |
| 启用所选 / 停用所选 | 配合 Ctrl/Shift 多选，一次启用/停用多条序列 |'
| 序列间隔 | **每条序列自己的值**：这条序列里相邻两个点之间等多久（默认 60ms；仅多点序列可改） |
| 删除 | 删除选中的序列；**Ctrl/Shift 可多选批量删** |
| 备注名 | 给这个坐标起个名字，比如"领取奖励""确认弹窗"，方便区分 |
| 点击方式 | **按一次 = 点一次**，或 **按一下开始 / 再按停止**（在该坐标持续连点） |
| 吞掉热键 | 默认开启，游戏不会收到这些键 |
| 点完把鼠标送回原处 | 作用于选中的点。开启后点完自动把鼠标移回原处，不打断你的操作 |

#### 批量录点（推荐用于全屏游戏）

全屏游戏里切出窗口会打断游戏，所以提供了这个模式：

1. 点「**记录坐标…**」（也可从托盘菜单进入）→ **连点器窗口自动隐藏**
2. 直接在你想要的位置点击，**每点一下记一个坐标**，可以连续点很多下
   - 每次点击的位置会弹一个**带序号的圆圈标记**，并且**一直留在屏幕上**
   - 序号就是点击顺序（1、2、3…），方便边录边确认点了哪儿、点了几个
3. 录完 **按 Esc 键**（或双击托盘图标）→ **屏幕上所有标记一起消失**，**连点器窗口弹回来**
4. 录到的坐标**自动保存为一条新序列**（不再弹确认框），并**自动进入设热键流程**：直接按一个键就配好这条序列的热键（按 Esc 跳过）
5. 回到「坐标点」页后，选中刚录的序列，下方**「该序列包含的点」**列表里
   序号 1、2、3… 与屏幕标记一一对应——一眼就能对上哪个是先点的

录点过程中：
- **点击不会被吞掉**——你点的按钮该响应的还是会响应
- **Esc 是结束录点的控制键**：结束后自动保存，不会漏给游戏
- **其它键盘按键照常放行**，你在游戏里用键盘不受影响
- 除**紧急停止键**外的所有热键暂时让开，避免不小心按到触发键，一边录一边连点

#### 一条序列 = 一串坐标，按录制顺序依次触发

批量录点录下的那串坐标就是一条序列，**按一下热键会按录制顺序依次点过去**，相邻两个点之间等这条序列自己的「序列间隔」，跑完一轮自动结束。

比如录了"领取奖励 → 确认弹窗 → 关闭结果"三个点、序列间隔设 **100ms**、热键 **F8**：
按一下 F8，就依次点这三处，每处间隔 100ms，正好走完一次完整流程。

- **点的先后** = 录制顺序；在「该序列包含的点」里想改顺序，删除序列重录即可
- **间隔多少** = 这条序列自己的「序列间隔」（选中序列后改，各序列互不影响）
- 多条**序列**也可以填同一个热键：按一下会先跑第一条、再跑第二条……
- 想临时停用一条序列，取消列表左侧勾选即可，其余照旧
- 单点序列的「点击方式」（点一次 / 连点）只在它单独一个热键时生效；多点序列固定依次点完一轮

**用法示例**：
1. 鼠标移到游戏里"领取奖励"按钮上 → 按 **F7**（或点「+ 记录当前鼠标位置」）
2. 在列表里选中刚加的那行 → 点「改键」→ 按下 **F8**
3. 在「备注名」里填上"领取奖励"
4. 以后无论鼠标在哪，按 **F8** 就会自动移过去点一下

重复第 1~3 步可以为"确认弹窗"等其它位置各配一个热键，互不干扰。

**双击列表项** = 立刻点过去，方便先确认位置对不对。

**旧版本的单个记录点会自动迁移**：如果你之前用过旧版并记录过一个坐标，升级后它会自动出现在列表里（名字叫"旧记录点"），热键和点击方式都保持不变，不需要重设。

**坐标换算经过专门验证**：屏幕坐标到 `SendInput` 绝对坐标的映射涉及多显示器、负坐标原点（副屏在主屏左侧/上方）、越界夹紧等边界，任何一处错了都会表现为"总是偏一点"。这部分已做成纯函数并覆盖了 7 项边界测试。

> 坐标按当前分辨率记录。换了分辨率或调整了显示器排布后，请重新记录一次。

### 程序行为

| 项目 | 说明 |
|---|---|
| 开机自动后台启动 | 通过**任务计划程序**注册（静默、不弹 UAC），开机后自动在托盘待命 |
| 关闭窗口时最小化到托盘 | 默认开启。点 × 不退出程序，只收进托盘 |
| 启动后直接隐藏到托盘 | 不打扰你 |
| 显示托盘气泡提示 | 状态变化时的轻提示 |
| **默认以管理员身份运行** | 默认**开启**。开启后每次启动都会自动请求管理员权限（一次 UAC 确认）；取消勾选则直接以普通权限启动、不弹 UAC |

关于最后一项的取舍：

- **建议保持开启**。很多游戏以管理员权限运行，而 Windows 的 UIPI 会静默丢弃普通权限进程发出的点击（表现为"点了没反应"）。开启后才能真正对所有游戏生效。
- 如果你只是改改设置、或玩的游戏本身不需要提权，可以关掉它——这样启动更清爽，不再看到 UAC 提示。
- 勾选或取消后，界面下方的权限状态行会实时告诉你**当前**处于什么权限、以及**下次启动**会怎样。勾选时程序会问你要不要立刻提权重启（因为设置只影响下次启动）。
- 也可以点「立即提权重启」按钮，不等下次启动就直接以管理员身份重启。
- 若某次 UAC 被取消，程序不会崩，而是以普通权限继续运行，并如实提示后果（不会假装已提权）。

## 关于管理员权限（重要）

如果游戏里点击没反应，**99% 是因为权限不够**。

Windows 有 **UIPI（用户界面特权隔离）** 机制：完整性级别低的进程，无法向完整性级别高的窗口注入输入。很多游戏（尤其是带反作弊的网游）以管理员权限运行，而普通权限的连点器发给它的点击会被**静默丢弃**——不报错，就是没效果。

因此程序提供「**默认以管理员身份运行**」开关（默认开启）：

- 开启时，每次启动会自动请求提权（一次 UAC 确认），点"是"即可
- 界面底部会实时显示状态：
  - `✓ 当前以管理员权限运行，可对所有游戏生效`
  - `⚠ 当前以普通权限运行。若游戏里点击无效，请勾选上方「默认以管理员身份运行」`
  - `⚠ 已勾选「默认以管理员身份运行」，但本次未提权（可能 UAC 被取消）`
- 随时可以点「立即提权重启」按钮，不必等下次启动

### 为什么不用「清单强制提权」

程序清单里用的是 `asInvoker`（不强制提权），是否提权交给上面的设置决定。原因是 `requestedExecutionLevel` **在编译期就固定了**：

- 若写成强制提权，这个 exe 就再也无法以普通权限启动，"是否默认以管理员身份运行"根本无法做成可选项
- 采用 `asInvoker` + 运行时自我提权后，两种行为都能覆盖：勾选走 `runas` 提权，不勾选就直接启动
- 默认值仍是开启，所以**默认行为与早期版本完全一致**，老用户不会感到变化

> 如果你运行过自动化测试，会看到"环境受限"的提示——那正是因为测试宿主的进程完整性级别低于当时前台运行的游戏进程，Windows 拦截了注入。这恰好印证了提权的必要性。

### 兼容性说明

- **绝大多数游戏可用**。基于 `SendInput`，与真实硬件输入走同一条通道，比 `mouse_event`（已废弃）兼容性好
- **少数带内核级反作弊的游戏**（如部分竞技网游）可能仍然拦截模拟输入。这属于反作弊的主动设计，无法也不应绕过
- 若某游戏使用 Raw Input 且只认硬件设备，也可尝试把「点击鼠标」改成其他键，或在游戏内设置里改用别的操作方式

## 配置文件（可选进阶用法）

所有设置都保存在 `%APPDATA%\GameClicker\config.json`，**可用记事本直接编辑**（每次启动读取，带中文注释）。

> 放在用户目录而不是程序目录，是为了让设置不会被程序更新 / 重新构建 / 移动文件夹影响。旧版放在程序目录的配置会在首次启动时**自动迁移过来**，老设置不会丢。

```json
{
  "triggerVk": 114,          // 键盘虚拟键码（114 = F3）
  "mode": 0,                 // 0=切换  1=按住
  "emergencyVk": 123,        // 紧急停止键（123 = F12），0=禁用
  "intervalMs": 50,          // 两次点击间隔（毫秒）
  "button": 0,               // 0=左键 1=右键 2=中键
  "holdMs": 15,              // 每次按下保持时长（毫秒）
  "followCursor": true,      // true=跟随鼠标  false=锁定位置
  "autoStartWithWindows": false,

  "recordHotkeyVk": 118,     // 记录坐标热键（118 = F7）：按下即新增一个坐标点
  "recordHotkeySwallow": true, // 吞掉该热键，游戏不会收到


  // 序列列表：批量录点的一条采集 = 一条序列，一串坐标共用一个热键
  // 按一下热键 → 按 points 的先后顺序依次点一遍，相邻两个点之间等 gapMs 毫秒
  // 只有 1 个点的序列：mode 才有意义（0=按一次点一次  1=按一下开始/再按停止）
  // hotkeyVk=0 表示没设热键（只能在界面上点"点过去"）
  // 多条序列填同一个 hotkeyVk：按一下会按先后顺序把每条都跑一遍
  "sequences": [
    {
      "name": "每日领奖",       // 序列备注名
      "hotkeyVk": 119,        // 119 = F8
      "enabled": true,        // false = 暂时停用这条序列的热键
      "gapMs": 100,           // 相邻两个点之间等多久（这条序列自己的值）
      "mode": 0,              // 仅单点序列有效
      "returnCursor": false,  // 跑完后把鼠标送回原处
      "points": [             // 点的顺序 = 触发顺序 = 录制顺序
        { "name": "领取奖励", "x": 960, "y": 540 },
        { "name": "确认弹窗", "x": 300, "y": 400 }
      ]
    }
  ],

  "runAsAdmin": true         // 启动时是否自动请求管理员权限
}
```

> `runAsAdmin` 若删掉或缺失，程序按 `true` 处理（与旧版行为一致）。
>
> 兼容三代旧配置：最老版（`hasPoint`/`pointX`）、上一版（`points` 坐标点列表）都会在读取时**自动迁移**成 `sequences` 序列，热键、开关、点击方式全部保留，老设置不会丢。程序保存后即以新格式写入。

常用虚拟键码：

| 键 | 码 | 键 | 码 | 键 | 码 |
|---|---|---|---|---|---|
| F1–F12 | 112–123 | F13–F24 | 124–135 | Space | 32 |
| A–Z | 65–90 | 0–9 | 48–57 | Enter | 13 |
| Insert | 45 | Delete | 46 | Home | 36 |
| End | 35 | PageUp | 33 | PageDown | 34 |
| 小键盘 0–9 | 96–105 | Esc | 27 | Tab | 9 |

默认值：连点触发键 **F3 (114)**、紧急停止 **F12 (123)**、记录坐标热键 **F7 (118)**。坐标点的热键由你自己设定，默认不占用任何按键。

编辑后重启连点器即可生效。

卸载：删除程序文件夹与 `%APPDATA%\GameClicker\`（配置、日志）；再到「任务计划程序」里删掉 `GameClickerAutoStart` 任务（若开启过开机自启），或重新运行程序取消勾选"开机自动后台启动"后保存。

## 常见问题

**Q：游戏里按触发键没反应？**
1. 确认以管理员身份运行（看界面底部的权限提示）
2. 确认触发键没被游戏占用——开启"吞掉触发键"时游戏收不到该键，但**若游戏用 DirectInput 独占键盘**可能仍需换个键
3. 换个不常用的功能键，如 F9、F10，避开游戏内置快捷键（注意别与记录坐标热键 F7 重复）

**Q：点击了但游戏没反应／偶尔漏点？**
把「按下时长」从 15ms 调大到 30–50ms。游戏帧率低时，太短的按下可能落在两帧之间。

**Q：连点过程中鼠标一动，点击位置就飘了？**
默认"跟随鼠标"模式就是跟着鼠标走的。想固定点一个位置，选「锁定启动时的位置」。

**Q：每次启动都弹 UAC，很烦？**
取消勾选「默认以管理员身份运行」，保存后下次启动就不再弹了。但请注意：如果游戏本身以管理员权限运行，普通权限的连点器点了会没反应。也可以保留勾选，只在需要安静时用命令行 `GameClicker.exe --no-elevate` 临时跳过提权。

**Q：勾了「默认以管理员身份运行」，但状态行说本次未提权？**
说明那次 UAC 提示被取消了（或系统策略拒绝）。程序会继续以普通权限运行并在状态行如实告知，不会假装已提权。想立刻生效可点「立即提权重启」。

**Q：按了记录点热键，鼠标没动／点偏了？**
1. 确认界面底部显示"以管理员权限运行"（普通权限下输入会被 UIPI 拦截，表现为毫无反应）
2. 先点「点过去」确认坐标对不对——如果这就偏了，重新记录一次坐标
3. 换过分辨率或改过显示器排布后，坐标会失准，需重新记录

**Q：记录点热键和连点触发键可以设成同一个吗？**
不建议，程序会直接拒绝（会提示"热键冲突"）。所有热键（触发键、紧急停止、记录坐标、以及每个坐标点）都不能重复。


**Q：会不会被游戏判定为外挂？**
本程序只模拟鼠标点击，不读写游戏内存、不修改游戏文件。但**任何自动化输入都可能违反部分游戏的用户协议**，请自行判断使用场景（单机游戏、挂机刷本等通常没问题）。请勿用于竞技类对战的作弊。

**Q：杀毒软件报警？**
程序未签名，且使用了全局键盘钩子（这是"全局热键"的标准实现方式），部分杀软会启发式报警。可加白名单。源码在 `src/` 下，欢迎自行审查、编译。

## 从源码编译

需要 Windows + .NET Framework 4.x（系统自带）：

```powershell
cd GameClicker
pwsh -File Build.ps1
```

只产出**一个** `dist\GameClicker.exe`。因为清单是 `asInvoker`，自动化测试可以直接用普通权限启动它（测试配置里把 `runAsAdmin` 设为 `false` 即不触发 UAC），不再需要额外的"不提权副本"。

源码结构：

| 文件 | 职责 |
|---|---|
| `Native.cs` | Win32 互操作：`SendInput`、低级钩子、`SetWindowsHookEx`、结构体定义、屏幕坐标换算 |
| `InputHook.cs` | 全局键鼠钩子：触发键、紧急停止、各坐标点热键、批量录点、过滤自身注入 |
| `ClickEngine.cs` | 连点引擎（独立高优先级线程，高精度计时）+ 序列点击 |
| `Config.cs` | 配置模型、持久化、JSON 注释剥离、进程名归一化 || `Startup.cs` | 开机自启（任务计划程序优先，注册表降级） |
| `Elevation.cs` | 按设置决定是否以管理员身份启动（提权、防递归、UAC 取消的降级处理） |
| `MainForm.cs` | 主界面（WinForms）+ 托盘 + 程序入口 |
| `app.manifest` | `asInvoker` 权限级别、高 DPI 感知、系统兼容性声明 |

> **关于测试中的"环境受限"提示**：本测试宿主进程的完整性级别低于当时前台运行的游戏进程，Windows 的 UIPI 机制会静默拦截 `SendInput`/`SetCursorPos`。这不是代码缺陷，恰恰证明了**必须提权**这一结论。`TestHarness` 会自动探测该条件并把受影响的项目标记为 `SKIP` 而非伪造通过；正式版已内置管理员清单，不会遇到此限制。
